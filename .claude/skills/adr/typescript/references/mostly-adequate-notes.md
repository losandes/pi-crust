# Mostly Adequate Guide — Notes

> **Background reading, not conventions.** The rules we actually follow are in
> [../functional-conventions.md](../functional-conventions.md). Read this file to
> learn a concept; read that one to know what to do.
>
> Caveats, so these notes are not mistaken for house style:
>
> - Examples are JavaScript. This repo is strict TypeScript.
> - The hand-rolled `curry`, `pipe`, `map`, `filter`, `prop`, and `trace` below are
>   illustrations of how they work. Import them from `ramda` instead of writing them.
> - `Maybe`, `Either`, and `Task` (Ch6) are **not used in this repo**. We use
>   discriminated-union result types and zod. See conventions §2.
> - The `memoize` in Ch3 keys on `JSON.stringify(args)`, which is order-dependent
>   and unbounded. Do not copy it into production code.
> - Ch5's React HOC composition predates hooks.

These notes were generated by claude-code to summarize [Professor Frisby's Mostly Adequate Guide to Functional Programming](https://mostly-adequate.gitbook.io/mostly-adequate-guide).

#### Ch1

1. **Pure Functions**

- Same output for same input
- No side effects (no external state changes, no I/O)
- Benefits: cacheable, portable, testable, parallelizable
- Return values, never modify arguments

```javascript
// Bad - impure with side effects
const updateCounter = (counter) => { counter.value += 1; };

// Good - pure function
const incrementCounter = (counter) => ({ ...counter, value: counter.value + 1 });
```

2. **Function Composition**

- Combine simple functions for complex behavior
- Data transformation pipelines
- Example: `const pipe = (f, g) => x => g(f(x))`

```javascript
// Implementing pipe composition
const pipe = (f, g) => x => g(f(x));
const toUpper = str => str.toUpperCase();
const exclaim = str => `${str}!`;
const shout = pipe(toUpper, exclaim);

shout('hello world'); // 'HELLO WORLD!'
```

3. **Avoid Imperative Code**

- Don't use statements changing state
- Use expressions returning values
- Replace loops with map, filter, reduce

```javascript
// Bad - imperative
const names = [];
for (let i = 0; i < people.length; i++) {
  if (people[i].age >= 18) {
    names.push(people[i].name);
  }
}

// Good - declarative
const names = people
  .filter(person => person.age >= 18)
  .map(person => person.name);
```

4. **Avoid Shared State**

- Don't rely on/modify external variables
- Pass all data as arguments
- Return new objects instead of mutating

```javascript
// Bad - shared state
let total = 0;
const addToTotal = (x) => { total += x; };

// Good - no shared state
const addToTotal = (total, x) => total + x;
const newTotal = addToTotal(0, 5);
```

5. **Avoid Mutation**

- Treat data as immutable
- Create new structures, don't modify existing
- Use spread, Object.assign, or Immer

```javascript
// Bad - mutation
const updateUser = (user) => {
  user.name = 'New Name';
  return user;
};

// Good - immutability
const updateUser = (user) => ({
  ...user,
  name: 'New Name'
});
```

6. **Declarative over Imperative**

- Express what, not how
- Focus on data transformation
- Increases clarity, reduces bugs

```javascript
// Bad - imperative
const doublePositives = (numbers) => {
  const results = [];
  for (let i = 0; i < numbers.length; i++) {
    if (numbers[i] > 0) {
      results.push(numbers[i] * 2);
    }
  }
  return results;
};

// Good - declarative
const doublePositives = numbers =>
  numbers
    .filter(n => n > 0)
    .map(n => n * 2);
```

7. **First-Class Functions**

- Assign to variables
- Pass as arguments
- Return from other functions

```javascript
// Functions as arguments
const applyOperation = (x, y, operation) => operation(x, y);
const add = (x, y) => x + y;
const multiply = (x, y) => x * y;

applyOperation(2, 3, add);      // 5
applyOperation(2, 3, multiply); // 6
```

8. **Project Guidelines**

- Arrow functions for conciseness
- TypeScript's readonly for immutability
- Higher-order functions over loops
- Compose small, single-purpose functions
- No state mutation in React components
- Isolate side effects from business logic

#### Ch2: First-Class Functions

1. **Avoid Redundant Wrappers**

- Pass functions directly, not wrapped

```javascript
// Bad - redundant wrapper
const getServerData = callback => ajaxCall(json => callback(json));

// Good - direct function passing
const getServerData = ajaxCall;
```

2. **Direct Function References**

- For same-argument calls, use direct references

```javascript
// Bad - unnecessary indirection
const BlogController = {
  index(posts) { return Views.index(posts); },
  show(post) { return Views.show(post); },
  create(attrs) { return Db.create(attrs); }
};

// Good - direct function references
const BlogController = {
  index: Views.index,
  show: Views.show,
  create: Db.create
};
```

3. **Generic, Reusable Functions**

- Abstract parameter names for reusability
- Avoid domain-specific names

```javascript
// Bad - domain specific
const validArticles = articles =>
  articles.filter(article => article !== null && article !== undefined);

// Good - generic and reusable
const compact = xs => xs.filter(x => x !== null && x !== undefined);
```

4. **Beware of `this` Binding**

- `this` can break first-class function passing
- Bind context or avoid `this`

```javascript
// Potential issue with `this`
fs.readFile('file.txt', db.save); // `this` context lost

// Fix by explicit binding
fs.readFile('file.txt', db.save.bind(db));

// Better - avoid `this` with pure functions
const save = (db, contents) => { /* pure save logic */ };
fs.readFile('file.txt', contents => save(db, contents));
```

5. **Design for Composition**

- Create pluggable functions
- Compatible input/output types

```javascript
// Functions designed for composition
const getPostId = post => post.id;
const getComments = id => api.get(`/comments?postId=${id}`);
const renderComments = comments => { /* render logic */ };

// Can be composed with pipe (left-to-right)
const renderPostComments = pipe(
  getPostId,
  getComments,
  renderComments
);
```

6. **Adapt at Boundaries**

- Modify only interface functions when APIs change
- First-class functions isolate change points

#### Ch3: Pure Functions

1. **Side Effects**

- Include: file changes, db mutations, API calls, state changes, DOM manipulation
- Control and isolate side effects

```javascript
// Side effect: modifies external state
let counter = 0;
const incrementCounter = () => {
  counter += 1; // Side effect
  return counter;
};

// Pure: no side effects
const incrementValue = (value) => value + 1;
```

2. **Memoization**

- Cache results of pure functions
- Same inputs always produce same outputs

```javascript
// Simple memoization
const memoize = (fn) => {
  const cache = {};
  return (...args) => {
    const key = JSON.stringify(args);
    if (!cache[key]) {
      cache[key] = fn(...args);
    }
    return cache[key];
  };
};

// Usage
const expensiveCalculation = memoize((x, y) => {
  console.log('Computing...');
  return x * y;
});

expensiveCalculation(2, 3); // Logs: Computing... Returns: 6
expensiveCalculation(2, 3); // No log, returns cached: 6
```

3. **Self-Documenting Code**

- Pure functions easier to understand by signature
- No hidden inputs/outputs
- Name by return value, not action

```javascript
// Impure: name doesn't reflect return, hidden dependency
const getUserData = () => {
  return fetch('/api/user').then(/* ... */);
};

// Pure: name reflects return, dependencies explicit
const fetchUserData = (apiClient, userId) => {
  return apiClient.get(`/user/${userId}`);
};
```

4. **Managing Side Effects**

- Control at boundaries
- Pure core with impure wrappers

```javascript
// Impure wrapper around pure core logic
const saveUserToDatabase = async (user) => {
  const validatedUser = validateUser(user); // Pure
  const normalizedUser = normalizeUserData(validatedUser); // Pure
  return database.save(normalizedUser); // Side effect at boundary
};
```

5. **Referential Transparency**

- Expression replaceable by its value
- Easier reasoning and refactoring
- Enables substitution-based debugging

```javascript
// Referentially transparent
const double = x => x * 2;

// Equivalent expressions:
double(3) + double(4);
6 + 8;
14;
```

6. **Immutability Patterns**

- Spread for new objects/arrays
- Object.freeze to prevent mutations
- map/filter/reduce over mutating methods
- Immer for deep immutability

```javascript
// Creating new data vs mutating
const addItem = (list, item) => [...list, item];
const updateItem = (list, index, newVal) => [
  ...list.slice(0, index),
  newVal,
  ...list.slice(index + 1)
];
```

#### Ch4: Currying

1. **Understanding Currying**

- Transform multi-arg function into sequence of single-arg functions

```javascript
// Regular function
const add = (x, y) => x + y;

// Curried version
const curriedAdd = x => y => x + y;

// Usage
add(2, 3);         // 5
curriedAdd(2)(3);  // 5
```

2. **Implementing Curry**

- Utility for currying any function

```javascript
// Simple curry implementation
const curry = (fn) => {
  const arity = fn.length;
  return function curried(...args) {
    if (args.length >= arity) {
      return fn(...args);
    }
    return (...moreArgs) => curried(...args, ...moreArgs);
  };
};

// Usage
const multiply = (x, y, z) => x * y * z;
const curriedMultiply = curry(multiply);

curriedMultiply(1)(2)(3); // 6
curriedMultiply(1, 2)(3); // 6
```

3. **Code Reuse with Currying**

- Create specialized from general functions

```javascript
// Reusable curried functions
const filter = curry((predicate, xs) => xs.filter(predicate));

// Creating specialized functions
const getPositives = filter(x => x > 0);
const getEvens = filter(x => x % 2 === 0);

// Using specialized functions
getPositives([1, -1, 2, -2]); // [1, 2]
getEvens([1, 2, 3, 4]);       // [2, 4]
```

4. **Data-Last Functions**

- Put data parameter last
- Enables easy partial application
- More composable

```javascript
// Data-last design pattern
const map = curry((fn, xs) => xs.map(fn));
const multiply = curry((a, b) => a * b);

// Create specialized mapping functions
const double = map(multiply(2));
const triple = map(multiply(3));

double([1, 2, 3]); // [2, 4, 6]
```

5. **Point-Free Style**

- Omit unnecessary parameter declarations
- More declarative, focused on transformations

```javascript
// Not point-free
const snakeCase = (str) => str.toLowerCase().replace(/\s+/g, '_');

// Point-free with curried functions and pipe
const toLowerCase = str => str.toLowerCase();
const replace = curry((regex, replacement, str) =>
  str.replace(regex, replacement));
const snakeCase = pipe(
  toLowerCase,
  replace(/\s+/g, '_')
);
```

6. **TypeScript and Currying**

- Use overloads or generics for type safety

```typescript
// TypeScript curry implementation
function curry<A, B, R>(fn: (a: A, b: B) => R):
  ((a: A) => (b: B) => R) & ((a: A, b: B) => R) {
  return function curried(a: A, b?: B) {
    if (arguments.length >= 2) {
      return fn(a, b as B);
    }
    return (b2: B) => fn(a, b2);
  } as any;
}
```

#### Ch5: Coding by Composing

1. **Pipe for Left-to-Right Composition**

- Intuitive data flow in code
- Create transformation pipelines

```javascript
// Multi-function pipe
const pipe = (...fns) =>
  fns.reduce((f, g) => (...args) => g(f(...args)));

// Usage
const slugify = pipe(
  str => str.toLowerCase(),
  str => str.replace(/\s+/g, '-')
);

slugify('Hello World'); // "hello-world"
```

2. **Debugging Compositions**

- Insert logging to inspect data flow
- Use trace utility

```javascript
// Debugging helper
const trace = curry((label, value) => {
  console.log(`${label}: ${value}`);
  return value;
});

// Usage in pipe
const normalizeUsername = pipe(
  trim,
  trace('after trim'),
  toLowerCase,
  trace('after lowercase')
);
```

3. **Async Composition**

- Special pipe for promises
- Chain async operations

```javascript
// Pipe for promises
const pipeP = (...fns) =>
  fns.reduce((f, g) => (...args) => f(...args).then(g));

// Usage with async functions
const fetchUserById = id => fetch(`/users/${id}`).then(r => r.json());
const getUsername = user => user.name;

const fetchUsernameById = pipeP(
  fetchUserById,
  getUsername
);
```

4. **Data Transformation Pipelines**

- Chain small, focused functions
- Step-by-step data flow

```javascript
// Processing pipeline
const processMovieData = pipe(
  filter(movie => movie.rating > 3),
  map(movie => ({
    title: movie.title,
    director: movie.director
  })),
  sortBy(prop('title'))
);
```

5. **Component Composition**

- Build complex from simple components
- Apply HOCs for cross-cutting concerns

```javascript
// React HOC composition
const withLoader = Component => props =>
  props.isLoading
    ? <LoadingSpinner />
    : <Component {...props} />;

const withErrorHandler = Component => props =>
  props.error
    ? <ErrorMessage error={props.error} />
    : <Component {...props} />;

// Compose with pipe (left-to-right)
const EnhancedMovieList = pipe(
  withErrorHandler,
  withLoader
)(MovieList);
```

6. **Property Transformations**

- Functions for specific properties
- Clear transformation sequence

```javascript
// Property operations
const prop = curry((propName, obj) => obj[propName]);
const setProp = curry((propName, value, obj) => ({...obj, [propName]: value}));

// Using with pipe
const transformUser = user => pipe(
  setProp('isActive', true),
  setProp('displayName', `${user.firstName} ${user.lastName}`)
```

#### Ch6: Example Application

1. **Maybe for Error Handling**

- Handle null/undefined safely
- Alternative to defensive code
- Maintain data flow

```javascript
// Simple Maybe implementation
const Maybe = {
  of: x => x === null || x === undefined ? Nothing : Just(x),
  Nothing: {
    map: () => Maybe.Nothing,
    chain: () => Maybe.Nothing,
    fold: (f, _) => f(),
  },
  Just: x => ({
    map: f => Maybe.of(f(x)),
    chain: f => f(x),
    fold: (_, g) => g(x),
  })
};

// Usage in pipeline
const getPhotoUrl = pipe(
  findUser,                  // might return null
  user => Maybe.of(user),    // wrap in Maybe
  maybe => maybe.map(u => u.photo),
  maybe => maybe.fold(
    () => '/default-photo.png', // fallback
    photo => photo.url
  )
);
```

2. **Either for Error Handling**

- Represent success/error
- Capture specific error info
- Maintain functional flow

```javascript
// Either implementation
const Either = {
  of: x => Right(x),
  Left: x => ({
    map: () => Either.Left(x),
    chain: () => Either.Left(x),
    fold: (f, _) => f(x),
  }),
  Right: x => ({
    map: f => Either.of(f(x)),
    chain: f => f(x),
    fold: (_, g) => g(x),
  })
};

// Validation pipeline
const validateUser = pipe(
  validateName,          // returns Right(user) or Left(error)
  either => either.chain(validateAge),
  either => either.fold(
    error => ({ success: false, message: error }),
    user => ({ success: true, user })
  )
);
```

3. **Declarative Data Fetching**

- Functional patterns with async ops
- Separate pure logic from IO effects

```javascript
// Task wrapper for promises
const Task = fork => ({
  fork,
  map: f => Task((rej, res) => fork(rej, x => res(f(x)))),
  chain: f => Task((rej, res) => fork(rej, x => f(x).fork(rej, res)))
});

const getJSON = url => Task((rej, res) =>
  fetch(url)
    .then(response => response.json())
    .then(res)
    .catch(rej)
);

// Data fetching pipeline
const getMovie = id => pipe(
  () => getJSON(`/movies/${id}`),
  task => task.map(formatMovie),
  task => task.fork(
    renderError,
    renderMovie
  )
)();
```

4. **Combine Functional Techniques**

- Mix currying, Maybe, Either, pipe
- Maintain flow with error handling

```javascript
// Data transformation with error handling
const getDirectorName = pipe(
  getJSON,                       // Task(response)
  task => task.map(movie =>
    Maybe.of(movie.director)     // handle null director
    .map(director => director.name)
    .fold(() => 'Unknown', name => name)
  ),
  task => task.fold(
    err => `Error: ${err.message}`,  // handle network errors
    name => name
  )
);
```

#### Ch7: Hindley-Milner Types

1. **Type Signatures**

- Describe function inputs/outputs
- Format: `functionName :: InputType -> OutputType`

```typescript
// capitalize :: String -> String
const capitalize = (s: string): string =>
  s.charAt(0).toUpperCase() + s.slice(1);
```

2. **Generics**

- Type variables for flexible code
- TypeScript: `<T>` represents any type

```typescript
// identity :: a -> a
const identity = <T>(x: T): T => x;
```

3. **Type Constraints**

- Types as function contracts
- Catch errors at compile time

```typescript
// head :: [a] -> a
const head = <T>(xs: ReadonlyArray<T>): T => {
  if (xs.length === 0) {
    throw new Error("Cannot get head of empty array");
  }
  return xs[0];
};
```

4. **Multi-Parameter Signatures**

- Show all types in order
- Show intermediate function types

```typescript
// add :: Number -> Number -> Number
const add = (a: number) => (b: number): number => a + b;

// filter :: (a -> Boolean) -> [a] -> [a]
const filter = <T>(predicate: (x: T) => boolean) =>
  (xs: ReadonlyArray<T>): ReadonlyArray<T> =>
    xs.filter(predicate);
```

5. **Pipeline Type Signatures**

- Show data flow in pipelines
- Match outputs to next inputs

```typescript
// characterCount :: String -> Number
const characterCount = pipe(
  toLowerCase,                   // String -> String
  (s: string) => s.split(' '),  // String -> String[]
  (arr: string[]) => arr.map(word => word.length), // String[] -> Number[]
  (lengths: number[]) => lengths.reduce((sum, n) => sum + n, 0) // Number[] -> Number
);
```

6. **Higher-Order Function Types**

- Common patterns in FP
- Templates for your functions

```typescript
// map :: (a -> b) -> [a] -> [b]
const map = <A, B>(fn: (x: A) => B) => (xs: ReadonlyArray<A>): ReadonlyArray<B> =>
  xs.map(fn);

// reduce :: ((b, a) -> b) -> b -> [a] -> b
const reduce = <A, B>(fn: (acc: B, x: A) => B) => (initial: B) => (xs: ReadonlyArray<A>): B =>
  xs.reduce(fn, initial);

// pipe :: ((a -> b), (b -> c), ..., (y -> z)) -> a -> z
const pipe = <A, B, C>(...fns: Array<(arg: any) => any>) =>
  (x: A): C => fns.reduce((acc, fn) => fn(acc), x);
```
